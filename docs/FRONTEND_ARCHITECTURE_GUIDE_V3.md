# Frontend Architecture Guide

**Version 3.0** · 19 August 2026 · supersedes v2 (May 2026)

This is the **narrative** guide: how the pieces fit together, and how a request travels
from a click to the database and back. Read it when you are meeting the codebase.

It is deliberately **not** the rulebook. Each rule has exactly one home in
[`rules/`](rules/README.md), and [`../CLAUDE.md`](../CLAUDE.md) carries the one-line version
of each. Where this guide states a rule it states it briefly and links there, so there is one
place to correct when a rule changes.

---

## What changed in v3

v2 described a template that no longer exists. The 0.2.0 release rebuilt most of the
infrastructure from a production app the template had seeded, and fixed two things that had
never worked.

| Area | v2 | v3 |
|---|---|---|
| **Authenticated requests** | Broken. The client called the backend origin cross-origin, so the httpOnly cookie never travelled, and the proxy answered `/api/v1/*` with `NextResponse.next()` into a 404. | Same-origin from the browser; the proxy rewrites to the backend after injecting the token and stripping spoofable hop headers. |
| **List pages** | A `DataTable` plus hand-rolled `useState` for page, search and filters. | The `DataView` system: URL-synced state, server-driven search/sort/paging, bulk actions, four explicit display states. |
| **Detail & edit** | A shadcn `Dialog` per module. | One shared `<Modal>`: side panel on desktop, bottom sheet on mobile, with an unsaved-work guard. |
| **Dates** | `formatDate` using `toLocaleDateString`. | A layer that separates instants from business dates, with ESLint enforcing it. |
| **Money** | `formatCurrency(amount: number)` — float maths. | `@/lib/numeric` on big.js; values are decimal strings end to end. |
| **Dropdowns** | Fed from the owning module's list hook. | `<ReferencePicker>` on ungated options routes — see [`rules/13`](rules/13-reference-data.md) for the 14 defects this shape caused. |
| **Errors** | None. Any throw white-screened the app. | Four boundaries, a `DataView` error slot, and a session-expiry dialog. |
| **Tests** | None. | Node's built-in runner, no dependency, covering the silent failure modes. |
| **Per-domain `store.ts`** | Generated by default. | Removed from the generator — list state lives in the URL. |
| **Docs** | This file at 1,700 lines restating every rule, plus a separate LLM prompt restating them again. | This file for the narrative; [`rules/`](rules/README.md) owns the rules; `CLAUDE.md` is the guardrail an AI tool reads. The third copy is gone. |

Full reasoning and what was deliberately left behind:
[`TEMPLATE_UPDATE_PLAN.md`](TEMPLATE_UPDATE_PLAN.md).

## 1. The shape

```
src/
├── app/
│   ├── layout.tsx                  root: fonts, providers, global surfaces
│   ├── error.tsx  global-error.tsx  not-found.tsx
│   ├── (auth)/login/page.tsx       unauthenticated
│   ├── (dashboard)/
│   │   ├── config.ts               nav items + ROUTES. Pure data, no JSX.
│   │   ├── layout.tsx              seeds auth + role stores, renders the shell
│   │   └── dashboard/
│   │       ├── layout.tsx          export const dynamic = "force-dynamic"
│   │       ├── error.tsx           a page can crash without taking the shell
│   │       └── <domain>/page.tsx   server component
│   └── api/auth/*                  BFF handlers — the only code that holds cookies
│
├── components/
│   ├── data-view/                  the list system
│   ├── ui/                         shadcn primitives + Modal, StatusBadge, PageHeader
│   ├── shared/                     DataTable, pickers, Field/DetailRow, lazy registry
│   ├── layout/                     DashboardShell, PageLayout
│   ├── loading/                    the global blocking overlay
│   ├── auth/                       SessionExpiredDialog
│   └── <domain>/                   one folder per domain
│
├── lib/
│   ├── api-client.ts               the one HTTP client
│   ├── auth/  permissions/         who you are, what you may do
│   ├── loading/                    blocking-mutation store
│   ├── numeric/  date-utils.ts  timezone.ts    values a human reads
│   ├── forms/                      dirty-check + reset-on-open
│   ├── reference/                  ungated dropdown feeds
│   ├── utilities/                  downloads, logger
│   └── <domain>/                   types → transformers → api → hooks
│
├── hooks/                          app-wide: media query, debounce, older-pages
├── proxy.ts                        route protection + the API rewrite
└── types/index.ts                  AppError, NavItem, shared shapes
```

**The one idea worth internalising:** a domain is a *pair* of folders — `lib/<domain>` for
data and `components/<domain>` for UI — and the dependency arrow only ever points one way,
from the page down to the client. Details: [`rules/01`](rules/01-module-anatomy.md).

## 2. The life of a request

A user opens the orders page and types "acme" into the search box.

**1. The URL changes.** `useDataView` debounces the keystrokes and writes
`?orders.q=acme` with `router.replace`. The URL is the state — not a `useState` beside it.
Back, Forward, refresh and a shared link all work for free.

**2. The hook re-runs.** `dv.apiParams` derives from the URL — `{ skip, limit, search,
sort_by, sort_order, …filters }` — and is both the argument to `useOrders` and part of its
query key. A new key means TanStack fetches; the old data stays on screen because lists set
`placeholderData: (prev) => prev`, so the table does not blink.

**3. `api.ts` calls the client.** `apiClient.get("/api/v1/orders", { params })`. A relative
path, on the app's own origin. Nothing here knows about tokens.

**4. The proxy does the auth.** `src/proxy.ts` matches `/api/v1/*`, reads the `access_token`
httpOnly cookie, sets `Authorization: Bearer …`, deletes six headers a browser could have
spoofed (`x-forwarded-for` and friends, which a backend reads for rate limits and audit),
and **rewrites** the request to the backend origin.

*This is the step that was broken.* v2 called `NextResponse.next()`, which falls through to a
404 because the app has no `/api/v1` route — and the client was calling the backend directly
anyway, cross-origin, where the cookie could not follow.

**5. The response comes back.** Non-2xx becomes an `AppError` with a `.statusCode` and a
readable `.message` (FastAPI's 422 array is flattened here). A 401 goes through
`withAuthRetry`: one deduplicated refresh, one retry, and if that fails the session flag goes
up rather than a navigation firing.

**6. The transformer runs.** `transformOrder(raw)` maps snake_case to camelCase and coerces
enums with `asEnum`. This is the only place the two vocabularies meet.

**7. The table renders.** `<DataView>` decides between four states — error, cold load, empty,
rows — and hands the rows to `<DataTable>`, which is a table above `md` and a stack of cards
below it.

## 3. The shared systems

Six systems carry the app. New work should **extend** them, not sidestep them.

### DataView — every list page

`useDataView` owns search, filters, sort and page, all in the URL. `<DataView>` composes the
toolbar, table and pagination, and owns the four display states.

The state living in the URL is what makes a list shareable and back/forward-aware. The
server doing the filtering is what stops "sort by newest" quietly meaning "the newest of
these twenty". → [`rules/07`](rules/07-list-pages.md)

### Modal — every detail, create and edit

Side panel on desktop, bottom sheet on phone. Tabs, a view↔edit pencil, a sticky footer.

Its most important prop is `isDirty`: with it, Escape, a backdrop click and the X ask before
throwing away typing, and the browser warns on tab close. Dirtiness compares against **the
state the form opened with**, never against empty — compare against empty and every edit
form is dirty before you touch it, and people learn to click through the prompt.

Internally it is split in two: a small `Modal` that latches the last open props so the exit
animation is not blank, and a `ModalPanel` that renders. → [`rules/09`](rules/09-forms-and-unsaved-work.md)

### The API client — one door out

Stateless, same-origin, one 401→refresh→retry path shared by every verb including the blob
helpers. → [`rules/03`](rules/03-api-layer.md)

### Blocking mutations — one overlay, one toast

`useBlockingMutation` raises a global overlay for the duration of a write and lowers it when
the invalidation has finished. The store is keyed by token, so two overlapping writes do not
lower it early. Success is announced once, from the hook.
→ [`rules/05`](rules/05-mutations-and-toasts.md)

### Reference pickers — the permission fix

A dropdown fed by the owning module's list endpoint needs that module's read permission,
which the person filling in the form often does not hold. `<ReferencePicker>` reads an
ungated `/options` route instead, and pins the current value server-side so the field never
goes blank. → [`rules/13`](rules/13-reference-data.md)

### The value layers — dates and numbers

`@/lib/date-utils` separates instants from business dates and pins one output format.
`@/lib/numeric` keeps money as decimal strings on big.js. Both exist to stop the same bug:
the same record reading differently on different machines. ESLint enforces both.
→ [`rules/12`](rules/12-dates-and-numbers.md)

## 4. State: the two-bucket rule

The most expensive mistake in this codebase's lineage is putting server data in a store.

| Bucket | Lives in | Examples |
|---|---|---|
| **Server state** — came from the backend, can change because someone else acted | TanStack Query | orders, the current user, permissions, reference options |
| **Client state** — exists only in this browser | Zustand or `useState` | which modal is open, the sidebar collapse, a wizard step, the blocking-overlay tokens |

**The test:** could this value change because another person did something? Then it is server
state, and a copy in a store is a copy that goes stale silently.

There is a third bucket that people reach for a store to hold: **list view state** — page,
search, filters, sort. That belongs in the **URL**, and `useDataView` puts it there.
→ [`rules/04`](rules/04-data-fetching.md)

## 5. Auth, end to end

Tokens live in httpOnly cookies. JavaScript never reads them, so an injected script has
nothing to steal.

```
POST /api/auth/login   → BFF handler calls the backend, sets access + refresh cookies
GET  /api/auth/me      → returns the user, silently refreshing if the access token expired
POST /api/auth/refresh → rotates both cookies
POST /api/auth/logout  → clears them
```

Those four route handlers are the **only** code that touches cookies. Everything else goes
through `proxy.ts`, which injects the header on the way past.

`(dashboard)/layout.tsx` seeds the auth and role stores from `/me`. It is deliberately not a
global provider — that would fire `/me` on the login page.

Permissions gate affordances, not access. The backend is the guard.
→ [`rules/06`](rules/06-permissions.md)

## 6. Adding a feature

`node ncube.js startdomain Order` scaffolds all of this. What it generates, and why:

**1. `src/lib/order/types.ts`** — wire shapes in snake_case, domain shapes in camelCase,
enums as `as const` arrays.

**2. `transformers.ts`** — `transformOrder(raw)`, plus its own local `asEnum`. The only place
the two vocabularies meet.

**3. `api.ts`** — one function per endpoint, a transformer on every response. No React.

**4. `hooks.ts`** — the key factory first, then queries, then mutations wrapping
`useBlockingMutation`.

**5. `index.ts`** — export only what components need.

**6. `components/order/order-view.tsx`** — `"use client"`, a `<DataView>`, permission-gated
actions.

**7. `order-form.tsx`** — react-hook-form + zod. `order-detail-modal.tsx` — a `<Modal>` with
`isDirty`.

**8. `app/(dashboard)/dashboard/order/page.tsx`** — a server component: metadata,
`<PageLayout>`, mount the view. Plus `loading.tsx`.

**9. Register it** — `ROUTES` and `dashboardNavItems` in `config.ts`, the keys in
`lib/permissions/`.

**10. Verify** — `npm run type-check && npm run lint && npm test && npm run build`.

## 7. What is deliberately absent

A template is as much about what it does not impose. Each of these was considered and left
out, with the reason.

| Absent | Why |
|---|---|
| **Multi-branch tenancy** | The production app this came from carries an `X-Active-Branch` header, a branch store and a switcher, plus a cache-clearing rule on switch. Real, and wrong to impose on every project. |
| **An analytics kit** | Stat tiles, breakdown bars and ranked lists exist upstream, but they need a `/stats` endpoint per module, which a new project does not have. |
| **Server Actions and RSC data fetching** | They split fetching across two systems that hold different copies of the same row. One owner beats a faster first paint here. |
| **A date library** | `Intl` formats; the app needs almost no date maths. 20 kB for `addDays` is a poor trade. |
| **Component and E2E tests** | Three dependencies and a config to assert what a person sees in a second. A login-and-visit-every-page smoke test is the right first addition — in a project, with a backend. |
| **Generated API types** | `openapi-typescript` would turn a backend rename into a compile error. Worth adding once you have a stable schema; the hand-written `Backend*` types are the interim. |
| **A tailwind.config.js** | Tailwind v4 is CSS-native. One file, `globals.css`, holds the tokens and the config. |
